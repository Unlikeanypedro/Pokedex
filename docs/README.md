## Contexto e evolução do projeto

Este projeto teve como ponto de partida a **Atividade 04 – Pokédex com Spring Boot + MongoDB**, proposta na disciplina, cujo objetivo inicial era dar continuidade à Atividade 03 – Pokédex com React + Vite, substituindo a utilização direta de um arquivo `pokedex-data.json` por uma API REST desenvolvida com Spring Boot e persistência em MongoDB.

Os documentos e especificações oficiais da atividade presentes neste repositório registram esse contexto inicial e definem os requisitos originais do projeto, incluindo a utilização do `Script_Pokedex.sql`, a criação da API REST, a integração entre React, Spring Boot e MongoDB, além das operações de cadastro, edição, consulta e exclusão de Pokémon.

### Expansão do escopo

Durante o desenvolvimento, o projeto deixou de ser tratado apenas como uma implementação pontual da atividade acadêmica e passou a ser planejado como uma **aplicação Pokédex mais completa, escalável e preparada para hospedagem e evolução futura**.

A expansão do projeto foi uma **decisão autoral do autor**, realizada a partir da proposta inicial da atividade. As funcionalidades adicionais, a ampliação do domínio, a organização das entidades e a preocupação com escalabilidade foram concebidas para transformar a implementação acadêmica inicial em uma aplicação com estrutura mais próxima de um projeto real.

Entre as principais expansões estão:

- Modelagem independente de Pokémon, tipos e treinadores;
- Relação entre treinadores e seus times;
- Sistema de movimentos;
- Relação entre Pokémon, movimentos e jogos;
- Builds de Pokémon;
- Cadastro de diferentes jogos e formatos;
- Sistema de efetividade dos tipos;
- Representação das principais séries do anime Pokémon;
- Estrutura preparada para expansão futura;
- Organização do backend visando manutenção e escalabilidade;
- Preparação do projeto para hospedagem e disponibilização como aplicação real.

Dessa forma, o projeto mantém os requisitos fundamentais definidos pela atividade original, mas não se limita a eles.

### Autoria das decisões de expansão

É importante destacar que a **decisão de ampliar o escopo do projeto e transformá-lo em uma aplicação mais completa foi uma iniciativa autoral**.

As especificações originais da atividade serviram como ponto de partida e referência para a implementação inicial. As alterações posteriores relacionadas à expansão do domínio, novas entidades, novas relações, organização das coleções e planejamento de escalabilidade foram decisões tomadas pelo autor com o objetivo de evoluir a aplicação para além do escopo mínimo solicitado.

Ferramentas de apoio, incluindo ferramentas de inteligência artificial, podem ter sido utilizadas durante o processo de desenvolvimento para auxílio técnico, revisão, esclarecimento de conceitos e implementação. Entretanto, **a concepção da expansão do projeto, a definição do escopo ampliado e as decisões de arquitetura e escalabilidade apresentadas nesta versão são de autoria do responsável pelo projeto**.

Portanto, a utilização de ferramentas de apoio não deve ser confundida com a autoria da proposta de expansão: **a ideia de transformar a atividade acadêmica inicial em um projeto de Pokédex mais amplo, escalável e hospedado foi uma iniciativa autoral**.

### Evolução do projeto

A evolução pode ser representada da seguinte forma:

```text
Atividade 03
React + Vite
      ↓
Atividade 04
React + Spring Boot + MongoDB
      ↓
Expansão autoral
      ↓
Pokédex ampliada
      ↓
Arquitetura escalável
      ↓
Projeto preparado para hospedagem
```

Assim, os documentos da atividade original permanecem como registro do **escopo inicial**, enquanto a implementação atual representa a evolução desse escopo para uma proposta mais abrangente.

O objetivo não foi substituir a atividade original, mas utilizá-la como **base para o desenvolvimento de um projeto maior**, preservando os requisitos acadêmicos enquanto novas funcionalidades e estruturas foram incorporadas.
